# Mac 干净环境复现

本目录提供犀牛鸟 WeKnora 课题三的零费用复现入口和验收标准。使用已提交源码、固定数据和本地固定响应模型，检查指标、服务重启后的持久化结果及索引重建后的应用向量缓存。全部业务源码、固定数据、依赖锁文件、迁移及质量工作流均在本仓库中。

## 给 Mac 端 AI 的任务

在本机接续执行以下步骤。用户设备为 Apple M4、macOS Tahoe 26.6.2；请实际核对系统、shell、Git 和 Docker Desktop，优先使用 Linux arm64 容器。Intel Mac 使用 Linux amd64。检查依赖时每次使用单条简单命令，直接读取本机输出；缺少图形安装权限时再请用户操作系统安装窗口。

1. 从 `https://github.com/Aokiuuz/WeKnora.git` 获取 `feat/public-dataset-workbench` 分支，在独立干净目录核对交付者提供的完整提交。分支 HEAD 会变化，验收必须固定完整提交。
2. 读取本文件、`kit/` 四个文件及 [GitHub 门禁指南](GITHUB-GATE.md)。已有数据与备份全部保留，复现使用全新目录和数据库。
3. 完成本机零费用固定回归，再使用全新数据库复跑。记录完整提交、数据身份、镜像标识、软件版本、全部指标和报告结果。
4. 根据下表核对结果，遇到失败先保留证据再定位原因。不得修改样本、阈值或断言来获得通过。
5. 另一个干净环境的验证、GitHub 工作流和合并阻断分别验收。前端体验安排在固定回归通过后。

本地检查、安装构建依赖和固定模型复现属于本任务范围。真实模型调用必须单独确认用途、模型、请求规模和费用上限。创建拉取请求、合并、修改远端规则与发布也需要对应授权。用户对指定提交推送的授权不自动授权其他远端变更。

## 一条命令运行

前提是 Docker Desktop 引擎已经启动，Git 可用，当前目录是本仓库根目录且工作区干净。先将 `git rev-parse HEAD` 与交付者提供的完整提交核对。然后执行：

```bash
bash docs/handoffs/2026-09-09-mac-github/kit/run-mac.sh "$PWD" "$(git rev-parse HEAD)"
```

Windows 用户提供的完整交付提交已核对后，上式从该提交生成源码快照。也可把第二个参数明确写为核对过的 40 位提交。复现入口仅读取仓库，在其父目录新建 `topic3-reproduction.XXXXXX`，所有运行数据均写入该目录。每次运行产生独立目录，保留停止的测试容器、数据库和日志。

构建阶段需要网络下载镜像和依赖。评测阶段使用 `--network none`，业务服务和固定响应模型在同一个容器内通过回环地址通信。默认命令不会执行真实供应商缓存实验，不需要模型密钥。

成功时终端显示返回值 0，结果目录的 `evidence/summary.json` 中 `status` 为 `passed`。失败时读取 `build.log`、`run.log` 和相应阶段日志；构建错误、依赖下载错误和指标回归应分别记录。

## 固定工程验收标准

表 1 定义本入口应保存的证据和数值判据。黄金样本的全部 13 项指标以[已提交阈值](../../../evaluation/regression/thresholds.json)为准；该阈值绑定数据内容身份。

| 对象 | 判据 | 输出 |
| --- | --- | --- |
| 黄金样本 | 2 题、13 项指标实例；召回率 0.75、准确率 0.5；全部逐项检查通过 | `evidence/golden/evaluation-regression.json` |
| 固定服务语料 | 20 题、24 段落、32 维固定散列向量 | `evidence/http/manifest.json` |
| 服务检索下限 | 召回率 0.7416666666666666；前三位归一化折损累计增益（Normalized Discounted Cumulative Gain at 3，NDCG@3）0.5310068874168308；容差 `1e-12` | 每轮 detail 和 manifest |
| 持久化 | 服务重启后成功任务、逐题结果与汇总可读且一致 | 两轮导出、SQLite 数据库、manifest |
| 应用向量缓存 | 首轮嵌入请求大于 0，第二轮为 0；参考首轮为 25 次 | `rounds[].attempts`、`supplier.jsonl` |
| 数据与版本 | 公开数据校验、数据异常测试、产品版本检查均返回 0 | 各阶段日志 |
| 真实模型费用 | 真实付费请求 0 | `paid_provider_requests`、容器禁外网配置 |

表中服务回归使用超文本传输协议（Hypertext Transfer Protocol，HTTP），先执行一轮评测，重启服务读取已保存结果，再重建索引执行第二轮。两轮逐题检索、生成和指标证据必须一致。固定回答来自测试数据，回答质量指标验证流程与公式，不代表真实模型的领域质量。

固定语料规范换行后的安全散列算法 256 位（Secure Hash Algorithm 256-bit，SHA-256）摘要为 `f32f37ab3388a42e1e671f64dd73e85198639011224b649c2cf5d345e3237ea8`。黄金样本的规范内容摘要为 `d8deca2c2ab7b77123130788c9082d0998ecbf76c1d8556952703045cc2556e1`，与原文件字节摘要的用途不同。入口记录原始数据文件摘要，并通过生产程序验证规范内容身份。

## 跨环境稳定性与质量泛化

至少保留三个独立运行目录：M4 首次运行、同一 M4 全新数据库复跑、另一个干净环境复跑。第三个环境可以是另一台设备或 GitHub 托管 Linux 环境；M4 内运行 amd64 仿真不能替代另一台 Intel Mac 的设备验证。

比较完整提交、数据身份、模型标识、有效参数、指标实例和数值。黄金样本按提交中的逐项容差比较；HTTP 独立复跑的相同指标应在 `1e-12` 内一致，并达到固定下限。耗时、日期、任务标识、处理器数量和不同架构的二进制摘要允许不同。任何数值漂移都应先记录，再调查排序、分词、依赖或架构差异。

真实模型的质量泛化需要另行固定开发集与独立留出集，按语言、领域、文档长度、有答案与无答案题分别报告样本数和逐题结果。当前公开目录包含中文机器阅读理解（Chinese Machine Reading Comprehension，CMRC）2018 与斯坦福问答数据集（Stanford Question Answering Dataset，SQuAD）2.0 各 24 题固定子集；SQuAD 子集含 8 道指定原文无答案题。子集结果不能代表官方完整基准，固定响应模型也不提供真实模型质量证据。

## 软件依赖与证据

容器固定 Go 1.26.7 及多架构基础镜像摘要。服务启用 C 语言互操作机制（C interoperability，CGO）及 SQLite 全文检索第五版（Full-Text Search 5，FTS5），构建标签为 `sqlite_fts5`，并提供 C/C++ 编译器、GoJieba 分词资源和服务所需原生依赖。Python 使用标准库。该路径不要求宿主原生构建 Go 服务。

额外系统包的实际版本保存到 `software-versions.txt`；实际链接模块列表、服务构建信息、二进制摘要、源码归档摘要、镜像标识均单独保存。模块信息从已编译程序读取，记录版本时保持离线。基础镜像固定不能保证未来解析出的系统包版本完全相同；需要相同软件环境时复用该架构已构建镜像，并保存传输文件摘要。不同架构分别保存镜像和结果。

源码业务基线为 `841b842ff7bb6aee518425b77faf3f9dc45e07d1`。该基线包含离线 OpenRouter 口径费用估算及分模型凭据输入；全局费用页面和运行时适配另行验收。用户指定保留实际调用渠道，用 OpenRouter 官方价格计算模拟费用，实际供应商费用与来源在审计中保持真实。固定复现账本字段用于合成计价算术验证，不能作为真实扣费或 OpenRouter 完整账单。

本目录的 Mac 执行与跨环境一致性须由接手者实测。记录真实状态，未执行项标为待验收。
